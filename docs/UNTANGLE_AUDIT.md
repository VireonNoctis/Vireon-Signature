# Signature Studio extraction and untangling audit

- Date: 2026-11-20
- Scope: standalone migration from `VireonNoctis/VireonNoctis.github.io` to `VireonNoctis/Vireon-Signature`
- Optional cleanup selection: neither Comments nor Tests
- Commit model: one migration commit on `main`

## 1. Previous structure and dependency map

The portfolio housed the Signature Studio beside unrelated portfolio concerns:

```text
src/main.ts
├── App.vue
├── portfolio directives
├── portfolio-global CSS and smooth-scroll runtime
└── signature route selection
    └── components/signature/SignatureStudio.vue
        ├── components/signature/SignatureAtmosphere.vue
        ├── components/signature/PretextHeadline.vue
        ├── signature/emailSignature.ts
        ├── localStorage lifecycle
        ├── clipboard fallbacks
        └── HTML file export
styles/
└── portfolio-wide tokens and signature-only styles
scripts/inline-pages.mjs
└── portfolio-specific route duplication and asset inlining
.github/workflows/pages.yml
└── portfolio-wide build and branch publishing
```

The page's actual rendering behavior had no need for the portfolio page, portfolio directives, Lenis, GSAP, profile data, or portfolio CSS. The feature did depend on global font variables and the root asset path, which were implicit dependencies.

## 2. Findings and structural fixes

### Hidden links

- **Entry-point coupling:** `src/main.ts` selected the signature route and also mounted the portfolio. A feature-only app change therefore depended on a portfolio entry point. The standalone app now has one root entry and one explicit app shell.
- **Scattered feature implementation:** editor UI, canvas components, domain renderer, styles and documentation lived in separate portfolio-level areas. They now share the `src/features/signature-studio/` boundary.
- **Implicit global style dependency:** signature styles relied on `--sans` and `--mono` supplied by portfolio CSS. These tokens now have an explicit, small owner in `src/styles/tokens.css`.
- **Asset-path coupling:** the logo was referenced from the portfolio root. The standalone app owns the asset in `public/` and uses relative paths for the project Pages base path.
- **Deployment coupling:** the route was generated by the portfolio's inline-pages script. The new repository owns a normal Vite build and a GitHub Pages workflow.

### Needless links

- **Editor logic and browser APIs were coupled to a large Vue component.** Draft persistence and export side effects now live in `useSignatureDraft.ts` and `useSignatureExport.ts`; the component coordinates state and presentation.
- **The domain renderer had no reason to depend on its old portfolio-level location.** It now lives under the feature's `domain/` folder and remains independent of Vue, the DOM, local storage and the clipboard.
- **Portfolio runtime dependencies were bundled into the signature entry.** The standalone entry no longer loads GSAP, Lenis, portfolio directives or portfolio components.

### Surplus and obsolete material

- The portfolio's `scripts/inline-pages.mjs`, multi-route bootstrap, portfolio components, Spotify tooling and broad portfolio styles are not part of this application and were not copied.
- GSAP and Lenis were not needed by the extracted feature and are not dependencies in this repository.
- The generic empty `.env.example` is removed because the browser-only app has no environment variables.
- The template's governance, security, code-of-conduct, support, issue templates and agent instructions are retained.

The domain module is the stable center. UI and composables depend on it; it does not depend on Vue or browser APIs. Canvas and glass styling never enter the HTML signature output.

## 6. Behavior and special cases preserved

- WebGL2 unavailable or context lost: the CSS atmospheric fallback remains available.
- Reduced-motion preference: the animated background and moving preview effects stop.
- Hidden browser tab: continuous shader animation pauses.
- User pause control: animation can be stopped and resumed.
- Local-storage access or parsing failure: the UI reports degraded draft persistence without blocking editing.
- Restored data is untrusted: only known fields and accepted enum/colour values are restored.
- Clipboard permission unavailable: legacy copy fallback is attempted; users also have raw HTML and file export options.
- Missing name or malformed email: export is blocked with a useful message and the first field is focused.
- Web links allow HTTP/HTTPS only and reject embedded credentials; images require HTTPS.
- Image blocking in recipients' clients is expected; text remains usable.
- No environment variables or backend are required.

## 7. Verification impact

- Repository validator remains dependency-free and now validates the selected JSON configuration and SHA-pinned Actions.
- Node's built-in test runner covers HTML escaping, URL safety, image URL policy, generated markup/plain text, and restored configuration validation.
- Vue type checking and Vite production build are part of CI.
- GitHub Pages deploys the standalone project using `/Vireon-Signature/` as its base path.
- Existing useful template validation and governance files are retained. No tests or comments were removed under the selected "neither" option.

## 8. Independent review and remaining limitations

Separate manual audit passes were performed over the entry point/import graph, domain and browser boundaries, build/deployment files, and repository documentation. Subagents were not available in this environment, so no parallel agent review is claimed.

The repository has no pre-existing npm lockfile. The current environment could not reach the npm registry to generate one; the workflows therefore use `npm install` rather than `npm ci`. Generate and commit a lockfile from a network-enabled development environment before treating dependency installation as fully reproducible.

The former portfolio URL `https://vireonnoctis.github.io/signature/` remains a separately generated page in the portfolio repository. This app deploys independently at `https://vireonnoctis.github.io/Vireon-Signature/`; automatic cross-repository synchronization of the old path is a separate deployment integration and is not silently assumed here.
